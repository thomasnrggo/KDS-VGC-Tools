# Localization

Status: **phase 1 shipped** (2026-10-13): English (default) and Spanish.

## Two separate settings

| Setting | Values | What it changes |
|---|---|---|
| **App language** | English, Español | The app's own text: buttons, labels, messages, errors |
| **Pokémon names** | English, Español (España), Español (Latinoamérica) | Official game terms: Pokémon, forms, moves, items, abilities, types, natures |

They're independent, e.g. an English interface with Spanish game terms. Both are picked from the
header's language menu (`LanguageMenu`) and stored per browser in localStorage (`appLanguage`,
`pokemonLanguage`), read through `useSyncExternalStore` like the theme. The server always renders
English; the client switches right after hydration. `<html lang>` follows the app language,
including before paint (layout.tsx's init script).

There's one Spanish for the app text. The game terms come in two Spanish variants because the games
themselves name things differently in Spain and Latin America: 254 moves, 37 abilities, 50 items and
2 types differ (Danza Espada / Danza de Espadas, Lucha / Pelea). Pokémon names are the same.

## English stays the stored language

Teams, pastes, exports, calc lookups, Firestore and shared links all keep the English names they
always had. Only what's **shown** is translated. Showdown and Poképaste only understand English, so
copy and export stay English whatever the setting.

## App text: `src/lib/i18n/messages/`

- `en.ts` is the source of truth for the shape; `es.ts` is typed `Messages`, so a missing or extra
  Spanish string fails `tsc`.
- Text that varies is a function (`imported: (count, variants) => …`), so each language writes its
  own grammar and plurals.
- A sentence with a link in it is split into `{ before, link, after }`, each part carrying its own
  spacing.
- Components call `useMessages()` (src/hooks/useLanguage.ts) and read `t.section.key`.
- Code outside React that builds a message during a user action (validation errors, toasts,
  Poképaste fetch errors, default names like "Team 3") calls `getMessages()` from
  `src/lib/i18n/settings.ts`. Tests run without `window`, so they always get English.
- Regulation labels are data ("Regulation M-C"); `t.common.regulationLabel` localizes them.

## Game terms: `src/data/names/<language>.json`

- Generated by `npm run generate:names` (scripts/generate-name-data.mjs) from PokeAPI's CSV export,
  only for names the app's own data uses. About 96 KB per language.
- Each table is keyed like the app's English data (normalized English name), so the lookup is
  "normalize the stored English name, read the translation". Abilities, moves and items are matched
  through PokeAPI's English name rather than its identifier ("as-one-glastrier" is "As One").
- **Latin-American Spanish borrows Spain's names for anything PokeAPI lacks**, notably Gen 9 items
  (Booster Energy, Covert Cloak, Loaded Dice).
- **Forms**: PokeAPI's Spanish form names are inconsistent: sometimes the full name ("Rotom Lavado",
  "Mega-Charizard X"), sometimes only the form ("Forma de Alola"), and missing for newer forms. A
  full name is kept, a form-only name becomes "Raichu (Forma de Alola)", and a missing one is built
  from `FORM_FALLBACKS` (Megas follow the games' "Mega-Garchomp Z" pattern; Tauros breeds, Palafin,
  Origin/Therian forms are listed). Anything else keeps its English form name in parentheses
  ("Tatsugiri (Droopy)") rather than a guessed translation.
- Anything not found falls back to English.
- Runtime: `usePokemonText()` returns a `PokemonText` translator (`species`, `speciesForm`, `move`,
  `item`, `ability`, `type`, `nature`). The language's file loads as its own chunk the first time
  it's needed; names show in English until it arrives.

## Search

Search matches the English name **and** the Pokémon-language name, ignoring accents
(`foldForSearch`), so "carchacrok", "panuelo" or "scarf" all work. This covers Opponents, My Teams
and both Speed Tiers views.

## Not translated yet

- **Unreleased or admin-only screens**: Team Builder (`PokemonEditor`, `SearchableSelect`), Damage
  Calculator, SpeedLine/RoundSpeedLine and the /admin pages. Team Builder's species/move/item pickers
  will also need to search translated names.
- **On-hold Team Report calcs/matchups screens** (`TEAM_REPORT_PREP_ENABLED = false`).
- **Descriptions**: ability/item/move short descriptions are Showdown's English text. PokeAPI has
  in-game descriptions in about 88% of cases, worded differently. To do in phase 2.
- **Suggested opponent tags** ("rain", "trick room") are stored data and stay English.
- **Season preset labels** come from the admin-defined seasons and aren't translated.
- **Other languages**: the generator takes any PokeAPI language (`LANGUAGES`); the app text needs a
  new `messages/<lang>.ts`.
